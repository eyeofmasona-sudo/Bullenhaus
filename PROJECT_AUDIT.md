# Аудит Проекта: Bullenhaus (Aurelius Unified Trade Desk)

На основе анализа репозитория и базы данных, вот полный аудит архитектуры, бизнес-логики, конфигурации Supabase и используемых технологий проекта.

## 1. Состояние базы данных Supabase (PostgreSQL)

База данных построена вокруг экосистемы **Supabase** с активным использованием продвинутых возможностей PostgreSQL.

### Существующие таблицы базы данных (схема public):
1. `users` — пользователи (профиль, кошелек, роль, KYC)
2. `clients` — клиенты
3. `leads` — лиды (потенциальные клиенты)
4. `support_tickets` — тикеты службы поддержки
5. `positions` — торговые позиции
6. `advertisers` — рекламодатели (вероятно для отслеживания трафика)
7. `referral_codes` — реферальная система
8. `orders` — ордера (сделки)
9. `transactions` — транзакции (депозиты/выводы)
10. `call_logs` — история звонков агентов
11. `price_overrides` — переопределение цен (спреды, комиссии)
12. `telephony_numbers` — номера IP-телефонии

### Функции базы данных (PostgreSQL routines):
1. `rls_auto_enable`
2. `set_updated_at` (Автоматическое обновление меток времени)
3. `handle_new_user` (Автоматическое создание профиля `public.users` при регистрации)
4. `get_my_role` (Определение роли текущего пользователя)
5. `approve_deposit`
6. `approve_withdrawal`

### Edge Functions (Серверлесс функции):
1. `crm-sync` (Статус: ACTIVE) — синхронизация с внешними CRM
2. `data-export` (Статус: ACTIVE) — выгрузка данных

**Row Level Security (RLS):** Строго настроено. Например, таблица `users` или `transactions` использует функцию `get_my_role()` для определения доступа: клиенты видят только свои данные, менеджеры/админы видят все.

## 2. Архитектура и Структура кода (Monorepo)

Проект использует архитектуру **Monorepo** на базе `pnpm workspaces` (управляется файлом `pnpm-workspace.yaml`).

### Основные компоненты (Пакеты):
- **Фронтенд (`artifacts/bullenhaus`)**: Основное веб-приложение, объединяющее клиентскую, CRM и административную части. Построено на **Vite + React 19**.
- **Бэкенд (`artifacts/api-server`)**: Внутренний API-сервер на базе **Node.js + Express** (вероятно, для выполнения тяжелых операций или интеграций, которые не подходят для Edge Functions).
- **Общие библиотеки (`lib/*`)**:
  - `db`: Схемы базы данных (Drizzle ORM).
  - `api-zod` и `api-spec`: Спецификации и контракты API.
  - `api-client-react`: React hooks для работы с API.

## 3. Бизнес-логика и Зоны Приложения

Приложение (согласно роутингу в `App.tsx`) строго разделено на три изолированные зоны, доступные на основе ролей (`client`, `agent`, `manager`, `director`, `admin`):

### 3.1. Трейдинговая платформа (Client Zone - `/trade`)
- **Целевая аудитория:** Обычные пользователи (клиенты).
- **Функционал:** Торговый терминал, мониторинг рынков, управление портфелем, история транзакций, KYC (верификация профиля), реферальная система, геймификация и система уведомлений.
- **Доступ:** Только для ролей `client` и `admin`.

### 3.2. CRM-система (Worker Zone - `/crm` / Aurelius Unified Trade Desk)
- **Целевая аудитория:** Сотрудники компании (агенты, менеджеры, директора).
- **Функционал:** 
  - Рабочая область агента (Agent Workspace)
  - Управление клиентами и VIP-клиентами
  - Интегрированная IP-телефония (`PhoneDialerContext`, `telephony_numbers`, `call_logs`)
  - Панели менеджера/директора для контроля за агентами
  - **AI Insights**: ИИ-аналитика для помощи агентам в продажах и оценке звонков.

### 3.3. Панель Администратора (Admin Zone - `/admin`)
- **Функционал:** Контроль рынков (Market Control), управление пользователями, KYC, одобрение депозитов/выводов средств (`approve_deposit`, `approve_withdrawal`), а также управление синхронизацией с внешними CRM.

## 4. Стек Технологий (Tech Stack)

### Frontend (bullenhaus)
- **UI/Стилизация:** Tailwind CSS v4, Radix UI (безголовые компоненты для доступности), Framer Motion (анимации), Lucide (иконки).
- **Управление состоянием:** Zustand, React Query (`@tanstack/react-query`).
- **Специфичные библиотеки:**
  - `lightweight-charts`, `recharts` — для построения графиков и торговых терминалов.
  - `socket.io-client` — WebSockets для работы с телефонией и/или реальными рыночными данными.
  - `react-i18next` — Интернационализация (мультиязычность).
  - `react-hook-form` + `zod` — Строгая валидация форм.

### Backend (api-server)
- **Фреймворк:** Express 5.
- **ORM / База данных:** Drizzle ORM, @supabase/supabase-js.
- **Логирование:** Pino (высокопроизводительный логгер).
- **Сборка:** Esbuild.

## 5. Выводы и потенциальные зоны развития

1. **Масштабируемость:** Архитектура монорепозитория заложена грамотно. Вынесение логики валидации (`api-zod`) и работы с БД (`lib/db`) в общие пакеты снижает дублирование кода между фронтендом и бэкендом.
2. **Безопасность:** Использование RLS на уровне базы данных PostgreSQL — отличная практика, защищающая от утечек данных даже в случае компрометации API серверов.
3. **Сложность телефонии:** Наличие `PhoneDialerContext` и таблиц телефонии говорит о том, что CRM является полноценным контакт-центром. Интеграция WebRTC и сокетов требует тщательного мониторинга.
4. **Синхронизация схем:** Drizzle ORM используется в пакете `db`, однако миграции созданы сырыми SQL-скриптами (`bullenhaus_full_migration.txt`). Рекомендуется выбрать один источник истины для схемы БД, чтобы избежать расхождений между SQL миграциями и моделями Drizzle.
